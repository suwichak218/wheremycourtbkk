## 1. ที่มาของปัญหาและความสำคัญ (Problem Statement)
(เล่าปัญหาของคนเล่นบาสใน กทม. เช่น สนามหายาก ข้อมูลกระจัดกระจาย ไม่รู้สภาพสนามจริง ฝนตกพื้นเปียก เดินทางไปแล้วเล่นไม่ได้ เสียเวลาและค่าใช้จ่าย)

## 2. จุดประสงค์ของโครงการและประโยชน์ที่คาดว่าจะได้รับ (Objectives & Expected Benefits)
- **จุดประสงค์:** เพื่อพัฒนาเว็บแอปพลิเคชันรวมพิกัดสนามบาส คัดกรองตามเงื่อนไข และให้ข้อมูลสถานะแบบเรียลไทม์
- **ประโยชน์:** ช่วยให้นักกีฬาประหยัดเวลาเลือกสนาม สร้างคอมมูนิตี้คนเล่นบาส และช่วยหารค่าสนามในร่มได้

## 3. ขอบเขตของโครงการ (Project Scope)
- **สิ่งที่ระบบทำได้ (In-Scope):** ค้นหาสนามตามพิกัด/รถไฟฟ้า, ตัวกรองราคา/เวลา, แผนที่ Google Maps, แสดงสิ่งอำนวยความสะดวก, รายงานสถานะสด, บอร์ดหาตี้
- **สิ่งที่ไม่ทำ (Out-of-Scope):** ระบบชำระเงินตัดบัตรเครดิตตรง (ทำเฉพาะจอง/หารค่าสนามผ่านการคุยภายนอก), ระบบแอปมือถือ Native (ทำเป็น Responsive Web)

## 4. Requirement Specification
### 4.1 Functional Requirements (FR)
- FR1: ระบบค้นหาพิกัดสนามตามตำแหน่งปัจจุบัน (GPS) และค้นหาตามย่าน
- FR2: ระบบคัดกรองตามราคา ประเภทสนาม เวลาเปิด-ปิด และระยะห่างรถไฟฟ้า
- FR3: ระบบแสดงหมุดพิกัดบน Google Maps และนำทาง
- FR4: ระบบแสดงสิ่งอำนวยความสะดวก (ไฟ, แป้น, ที่จอดรถ, น้ำดื่ม)
- FR5: ระบบรายงานสถานะสด (Live Status & Crowd level)
- FR6: ระบบบอร์ดหาตี้และหารค่าคอร์ท (Find Teammates)
- FR7: ระบบรีวิวและอัปโหลดภาพสภาพสนาม
### 4.2 Non-Functional Requirements (NFR)
- NFR1 (Performance): หน้าเว็บและแผนที่ต้องโหลดแสดงผลเสร็จสิ้นภายใน 3 วินาที
- NFR2 (Usability): รองรับ Responsive Design บนมือถือและคอมพิวเตอร์อย่างราบรื่น
- NFR3 (Reliability): ใช้งานแผนที่ได้ต่อเนื่อง 99% ผ่าน Google Maps API
