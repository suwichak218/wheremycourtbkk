## 1. ที่มาของปัญหาและความสำคัญ

กีฬาบาสเกตบอลเป็นหนึ่งในกีฬายอดนิยมของกลุ่มนักเรียน นิสิต นักศึกษา และคนวัยทำงานในเขตกรุงเทพมหานคร เนื่องจากเป็นกีฬาที่ใช้พื้นที่จำกัดและสามารถรวมกลุ่มเล่นได้ง่าย อย่างไรก็ตาม ผู้เล่นบาสเกตบอลในเมืองหลวงมักประสบปัญหาสำคัญหลายประการในการเข้าถึงสถานที่เล่น:

1. **ข้อมูลสนามกระจัดกระจาย:** ข้อมูลสนามบาสเกตบอลในกรุงเทพฯ ส่วนใหญ่กระจายอยู่ตามเพจ Facebook หรือกระทู้เก่า ทำให้ผู้เล่น โดยเฉพาะผู้ที่ย้ายที่อยู่ใหม่หรือเดินทางไปต่างย่าน ค้นหาสนามที่เหมาะสมได้ยากลำบาก
2. **เงื่อนไขและข้อจำกัดการเดินทาง:** นักกีฬาและผู้เล่นส่วนใหญ่พึ่งพาระบบขนส่งมวลชนสาธารณะ (BTS / MRT) เป็นหลัก การขาดตัวกรองระยะทางจากสถานีรถไฟฟ้าทำให้เกิดความไม่สะดวกในการวางแผนเดินทาง
3. **ความไม่แน่นอนของสภาพสนามและสิ่งอำนวยความสะดวก:** ข้อมูลพื้นฐานที่จำเป็นต่อการเล่น เช่น ประเภทพื้นผิว (ปูน, ยาง, ปาเกต์), สถานะของแป้นและตาข่าย, การเปิดไฟสปอร์ตไลท์ช่วงค่ำ, จุดบริการน้ำดื่ม และห้องน้ำ มักไม่มีระบุไว้อย่างชัดเจน ทำให้ผู้เล่นต้องเดินทางไปสำรวจเอง
4. **ปัญหาความไม่พร้อมใช้งานแบบเรียลไทม์:** ผู้เล่นจำนวนมากเสียเวลาเดินทางไปยังสนาม แต่กลับพบว่าไม่สามารถเล่นได้จริง เช่น เกิดฝนตกทำให้พื้นลื่น, มีการจัดกิจกรรมปิดสนาม, หรือจำนวนผู้เล่นหนาแน่นจนล้นคิว
5. **ภาระค่าใช้จ่ายในการเช่าสนามในร่ม:** สนามบาสเกตบอลในร่มคุณภาพดีมีค่าบริการรายชั่วโมงค่อนข้างสูง แต่ผู้เล่นมักประสบปัญหาขาดแคลนสมาชิกในการแชร์ค่าใช้จ่าย หรือขาดผู้เล่นร่วมทีมสำหรับจัดเกมการเล่น

จากสภาพปัญหาดังกล่าว คณะผู้จัดทำจึงเล็งเห็นความสำคัญในการพัฒนาเว็บแอปพลิเคชัน **"wheremycourtbkk"** เพื่อเป็นแพลตฟอร์มศูนย์รวมพิกัดและข้อมูลสนามบาสเกตบอลในกรุงเทพมหานคร พร้อมระบบค้นหาเชิงตำแหน่ง , ระบบคัดกรอง, แผนที่นำทาง, ระบบรายงานสถานะสดแบบเรียลไทม์ และพื้นที่สำหรับจับคู่ผู้เล่นเพื่อแบ่งปันค่าใช้จ่าย ซึ่งจะช่วยยกระดับประสบการณ์ของผู้เล่น ลดความสูญเสียเวลาและค่าใช้จ่ายในการเดินทาง ตลอดจนส่งเสริมการสร้างเสริมสุขภาพและสร้างคอมมูนิตี้คนรักกีฬาบาสเกตบอลในเขตเมืองอย่างยั่งยืน

## 2. จุดประสงค์ของโครงการและประโยชน์ที่คาดว่าจะได้รับ

### จุดประสงค์ของโครงการ 
1. เพื่อออกแบบและพัฒนาเว็บแอปพลิเคชันรวบรวมฐานข้อมูลพิกัดและรายละเอียดสนามบาสเกตบอลในเขตกรุงเทพมหานคร
2. เพื่อพัฒนาระบบสืบค้นและคัดกรองข้อมูล ที่สามารถจัดกลุ่มสนามตามพิกัด, ระยะห่างจากโครงข่ายรถไฟฟ้า (BTS/MRT), ค่าบริการ, เวลาเปิด-ปิด และสภาพพื้นผิวสนาม
3. เพื่อพัฒนาระบบรายงานสถานะการใช้งานสนามแบบเรียลไทม์ ให้ผู้เล่นสามารถตรวจสอบสภาพสนาม สภาพอากาศ และความหนาแน่นก่อนการเดินทาง
4. เพื่อสร้างแพลตฟอร์มจับคู่ผู้เล่น สำหรับจัดตั้งกลุ่มเล่นกีฬา และเป็นตัวกลางประสานการแบ่งปันภาระค่าใช้จ่ายในการเช่าสนามในร่ม

### ประโยชน์ที่คาดว่าจะได้รับ
* **สำหรับผู้เล่นทั่วไปและนักกีฬา:** ลดระยะเวลาและค่าใช้จ่ายในการตระเวนหาสนาม, ลดความเสี่ยงในการเดินทางไปแล้วไม่สามารถเล่นได้, และช่วยประหยัดค่าบริการสนามในร่มผ่านระบบแชร์ค่าคอร์ท
* **สำหรับสังคมและชุมชน:** ส่งเสริมการออกกำลังกาย การใช้พื้นที่สาธารณะของเมืองอย่างคุ้มค่า และสร้างเครือข่ายคอมมูนิตี้คนรักกีฬาบาสเกตบอลที่เข้มแข็ง

## 3. ขอบเขตของโครงการ

### สิ่งที่ระบบทำได้
* **การจัดการและแสดงผลข้อมูลเชิงพื้นที่:**
  - ค้นหาสนามตามพิกัดปัจจุบันของผู้ใช้ (User Location / Near Me) และการค้นหาด้วยคำค้น (ชื่อสนาม, ถนน, ย่าน, สถานีรถไฟฟ้า)
  - แสดงหมุดพิกัดสนามบนแผนที่ พร้อมปุ่มเปิดเส้นทางนำทาง เชื่อมต่อไปยัง Google Maps
* **ระบบการกรองข้อมูลแบบละเอียด:**
  - กรองตามสถานะค่าใช้จ่าย (สนามฟรี / สนามเช่า พร้อมช่วงราคาต่อชั่วโมง)
  - กรองตามประเภทสนาม (Indoor / Outdoor) และประเภทพื้นผิว (ปูน / ยางสังเคราะห์ / ปาเกต์)
  - กรองตามระยะทางจากสถานีรถไฟฟ้า BTS หรือ MRT (เช่น ภายใน 500 ม., 1 กม.)
  - กรองตามสถานะการเปิดให้บริการ (เปิดอยู่ตอนนี้ / สนามที่มีไฟกลางคืน)
* **ระบบข้อมูลและสิ่งอำนวยความสะดวก:**
  - แสดงรายละเอียดเชิงลึก: จำนวนแป้นบาส, สภาพตาข่าย, ไฟสปอร์ตไลท์, ห้องน้ำ, ที่จอดรถ และจุดบริการน้ำดื่ม
* **ระบบความร่วมมือของผู้ใช้งาน:**
  - ระบบรายงานสถานะสนามสด เช่น ความหนาแน่นของผู้เล่น, สภาพพื้นสนาม (เปียก/แห้ง), และสถานะไฟสนาม
  - กระดานประกาศหาทีมและหาคนแชร์ค่าเช่าสนาม พร้อมข้อมูลติดต่อภายนอก
  - ระบบประเมิน ให้คะแนนดาว (1-5 ดาว) และอัปโหลดภาพถ่ายสภาพสนามจริงประกอบรีวิว
* **สถาปัตยกรรมระบบ :**
  - ระบบทำงานในรูปแบบ Responsive Web Application รองรับการใช้งานผ่าน Web Browser ทั้งบนคอมพิวเตอร์ แท็บเล็ต และสมาร์ตโฟน

### สิ่งที่ไม่ทำในขอบเขตโครงการ (Out-of-Scope)
* **ระบบชำระเงินโดยตรง :** ระบบไม่รองรับการตัดบัตรเครดิต, พร้อมเพย์, หรือกระเป๋าเงินอิเล็กทรอนิกส์บนหน้าเว็บ (การแชร์ค่าสนามและการจองจะกระทำผ่านการติดต่อกันโดยตรงระหว่างผู้ใช้ผ่านช่องทางภายนอก เช่น LINE หรือเบอร์โทรศัพท์)
* **แอปพลิเคชันแบบ Native (Mobile App):** ไม่ได้พัฒนาเป็นแอปพลิเคชันสำหรับดาวน์โหลดผ่าน App Store (iOS) หรือ Play Store (Android) โดยตรง แต่ใช้มาตรฐาน Web Responsive แทน
* **ระบบกล้องวงจรปิด/IoT ตรวจจับอัตโนมัติ:** การรายงานสถานะสนามแบบเรียลไทม์จะอิงจากการกรอกข้อมูลของผู้ใช้งานจริง ไม่ได้เชื่อมต่อเซนเซอร์ฮาร์ดแวร์หรือกล้อง AI ประมวลผลภาพ
* **การครอบคลุมพื้นที่นอกเขตกรุงเทพฯ และปริมณฑล:** ฐานข้อมูลเริ่มต้นจะจำกัดเฉพาะพื้นที่กรุงเทพมหานครและสถานีรถไฟฟ้าส่วนต่อขยายเท่านั้น

## 4. Requirement Specification
### 4.1 Functional Requirements (FR)
- FR1: ระบบค้นหาพิกัดสนามตามตำแหน่งปัจจุบัน (GPS) และค้นหาตามย่าน
- FR2: ระบบคัดกรองตามราคา ประเภทสนาม เวลาเปิด-ปิด และระยะห่างรถไฟฟ้า
- FR3: ระบบแสดงหมุดพิกัดบน Google Maps และนำทาง
- FR4: ระบบแสดงสิ่งอำนวยความสะดวก (ไฟ, แป้น, ที่จอดรถ, น้ำดื่ม)
- FR5: ระบบรายงานสถานะสด 
- FR6: ระบบบอร์ดหาตี้และหารค่าคอร์ท 
- FR7: ระบบรีวิวและอัปโหลดภาพสภาพสนาม
### 4.2 Non-Functional Requirements (NFR)
- NFR1 (Performance): หน้าเว็บและแผนที่ต้องโหลดแสดงผลเสร็จสิ้นภายใน 3 วินาที
- NFR2 (Usability): รองรับ Responsive Design บนมือถือและคอมพิวเตอร์อย่างราบรื่น
- NFR3 (Reliability): ใช้งานแผนที่ได้ต่อเนื่อง 99% ผ่าน Google Maps API
